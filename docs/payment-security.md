# 결제 및 MongoDB 보안 운영 가이드

## 현재 구현된 보호 장치

구매 주문은 서버에서 게임 가격을 다시 조회하고 저장하므로 브라우저가 보낸 금액을 신뢰하지 않습니다. 결제 승인도 서버의 Toss secret key로만 수행하고, `orderId`를 idempotency key로 사용해 중복 승인 위험을 줄였습니다. 스팀키 배정은 `AVAILABLE` 한 건을 `SOLD`로 바꾸는 MongoDB 원자적 업데이트라 동시 구매가 같은 키를 받을 수 없습니다.

구매자의 이름·이메일·전화번호와 스팀키는 AES-256-GCM으로 암호화하여 저장합니다. 이메일 중복 조회에는 원문 대신 keyed SHA-256 해시를 사용합니다. 관리자 API에서만 복호화하며, 공개 API에는 개인정보를 반환하지 않습니다.

## 운영 전 필수 설정

`.env`에 `TOSS_CLIENT_KEY`, `TOSS_SECRET_KEY`, `PAYMENT_DATA_ENCRYPTION_KEY`, `RESEND_API_KEY`, `PUBLIC_BASE_URL`을 설정해야 합니다. 테스트 운영에서는 `test_ck_`와 `test_sk_` 키를 사용하고, 실결제 전환 때만 Toss 콘솔에서 발급한 live 키로 교체합니다. 실제 값은 GitHub, 채팅, 로그에 절대 커밋하지 않습니다.

`PAYMENT_DATA_ENCRYPTION_KEY`는 배포 서버의 비밀 저장소에 보관하고 백업합니다. 이 키를 잃으면 기존 개인정보와 스팀키를 복호화할 수 없습니다. 키를 교체할 때는 기존 데이터 재암호화 마이그레이션을 먼저 수행해야 합니다.

## MongoDB 권장 설정

MongoDB는 애플리케이션 서버의 사설 네트워크에서만 접근하게 하고, `bindIp`를 `127.0.0.1` 또는 내부 사설 IP로 제한합니다. 관리자 계정에는 `readWrite`를 필요한 데이터베이스에만 부여하고 root 계정을 애플리케이션 URI에 사용하지 않습니다. 전송 구간 TLS, 인증 활성화, 정기 백업 및 복구 테스트를 켭니다.

서버 방화벽에서는 SSH를 허용된 IP 또는 VPN으로 제한하고 비밀번호 로그인 대신 SSH 키를 사용합니다. 운영 서버에 전달된 비밀번호는 이미 노출된 것으로 간주하여 즉시 변경해야 합니다. Node 프로세스와 `.env` 파일은 일반 사용자에게 읽기 권한을 주지 않습니다.

## 결제 운영 체크리스트

Toss 콘솔에 `https://your-domain.example/api/payments/toss/webhook`을 웹훅 URL로 등록합니다. 웹훅은 보조 상태 동기화 수단이며, 최종 승인과 금액 검증은 반드시 `/payments/confirm` 응답으로 판단합니다. Resend가 일시적으로 실패하면 주문은 결제 완료·발송 대기로 남기고 관리자 화면에서 확인할 수 있도록 했습니다.

실결제 전환 전에는 테스트 카드로 성공·취소·금액 변조·재시도·재고 부족·이메일 실패를 각각 검증합니다. 환불/취소 정책과 개인정보 보관·파기 기간은 실제 운영 정책 및 관련 법률 검토 후 확정해야 합니다.
